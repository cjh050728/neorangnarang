# 너랑나랑

닉네임으로 가입해서 내 프로필을 만들면 프로필 저장소(가상 프로필 36명)와 하나씩 비교해서, **서로 잘 맞는 순서로 추천하고 1위의 이유를 화면에 보여주는** 매칭 로직입니다.
연인 찾기 / 친구 찾기 두 가지 모드가 있고, 무엇을 중요하게 볼지 각자 정할 수 있습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 (프로필 입력, 결과 표시) |
| `matching.js` | 매칭 로직 (거르기 → 점수 → 이유) |
| `chat.js` | 채팅 자동 답장 (가상 프로필용) |
| `llm.js` | 나랑이: Ollama(LLM)로 "왜 이 사람인지" 설명 |
| `profiles.js` | 프로필 저장소 (가상 프로필 36명, 닉네임·자기소개 포함) |
| `photos/` | 연인 모드 프로필 사진 14장 (AI 생성 가상 인물) |

## 흐름

```
회원가입(닉네임) → 프로필 설정 → 내 프로필 올리기 → 저장소의 프로필과 하나씩 비교 → ① 거르기 → ② 점수 → 점수 순으로 추천 + ③ 이유 설명
```

## ① 거르기 (하나라도 걸리면 탈락)

- 나 자신은 추천하지 않음
- 찾는 관계(연인/친구)가 서로 같아야 함
- 성별, 나이 범위, 키 범위(연인만), 흡연, 같은 종교 조건
- **양방향으로 확인**: 상대가 내 조건에 맞아도, 내가 상대 조건에 안 맞으면 탈락
  → "나한테도 잘 맞고, 그 사람한테도 내가 잘 맞게"
- 조건에 맞는 사람이 0명이면 안내 문구를 보여주고, 누가 왜 걸러졌는지 목록으로 보여줌

## ② 점수 (100점)

### 계산 방법

| 항목 | 계산 | 종류 |
|---|---|---|
| 관심사 | 자카드 유사도 = 겹친 수 ÷ 합친 수 | 서로 같음 |
| 성격 | 내가 원하는 성격 3개 중 상대가 가진 개수 ÷ 3 | 방향 있음 |
| 상 | 상대의 상이 내가 선호하는 상이면 1, 아니면 0 | 방향 있음 |
| 연락·데이트 스타일, 성향 | 3단계 중 차이: 같음 1 / 한 칸 0.5 / 두 칸 0 | 서로 같음 |
| 생활 패턴, 지역 | 같으면 1, 다르면 0 | 서로 같음 |
| 나이 | max(0, 1 − 나이 차 ÷ 5) — 가까울수록 높고 0 아래로 안 내려감 | 서로 같음 |

### 기본 배점

| 항목 | 연인 | 친구 | 이유 |
|---|---|---|---|
| 관심사 | 20 | 30 | 같이 할 거리가 있어야 함. 친구는 이게 제일 중요 |
| 성격 | 20 | 20 | 어떤 사람인지가 관심사만큼 중요 |
| 연락 스타일 | 10 | 10 | 연락 빈도 차이는 실제로 자주 부딪히는 부분 |
| 상 | 10 | 0 | 연인은 외모 취향도 반영, 친구는 상관없음 |
| 생활 패턴 | 10 | 5 | 아침형/저녁형이 같으면 만날 시간이 맞음 |
| 데이트(노는) 스타일 | 10 | 10 | 집콕파와 밖으로파는 주말 보내는 방식이 다름 |
| 성향 | 5 | 10 | 내향/외향은 성격 키워드와 겹쳐서 연인은 작게 |
| 나이 | 10 | 10 | 범위는 이미 거르기에서 확인, 비슷할수록 조금 더 |
| 지역 | 5 | 5 | 가까우면 만나기 쉬움 |

### 각자 중요도 정하기

"내 기준으로 바꾸기"를 켜면 항목마다 중요도를 고를 수 있습니다.
안 중요해(0) / 조금(1) / 보통(2) / 매우 중요(3) → 고른 값을 합쳐서 100점으로 환산합니다.

### 서로 점수

- **나 기준 점수**: 내 중요도로 상대를 계산
- **상대 기준 점수**: 상대 중요도로 나를 계산 (가상 프로필은 기본 배점 사용)
- **최종 점수 = 두 점수의 평균**

성격과 상은 방향이 있어서, 내가 상대를 좋아해도 상대가 나를 원하지 않으면 점수가 내려갑니다. 그래서 한쪽만 좋아하는 매칭이 위로 올라오지 않습니다.

## ③ 이유

1위 카드에 이렇게 보여줍니다.
- 점수를 가장 많이 받은 항목 3개와 근거 (예: "관심사: 겹친 관심사 러닝, 노래, OTT (3/5) → +12.0점")
- 2위보다 몇 점 높은지, 어떤 항목에서 차이가 났는지
- 나 기준 / 상대 기준 점수

모든 후보는 펼치면 항목별 점수표(근거, 나 기준, 상대 기준)를 볼 수 있습니다.

## 예시 결과 (화면의 기본 예시 프로필, 연인 모드)

| 순위 | 닉네임 | 최종 | 나 기준 / 상대 기준 |
|---|---|---|---|
| 1 | 노래하는곰 | 88.0 | 88.0 / 88.0 |
| 2 | 달리는댕댕이 | 72.5 | 80.8 / 64.2 |
| 3 | 요리하는댕댕 | 69.0 | 69.0 / 69.0 |
| 4 | 산책댕댕 | 66.8 | 66.8 / 66.8 |
| 5 | 기타치는토끼 | 55.5 | 47.2 / 63.8 |

노래하는곰이 1위인 이유: 원하는 성격 3개(다정함·배려심·유머러스)를 모두 가졌고(+20.0), 관심사 3개가 겹치고(+12.0), 연락 스타일이 같음(+10.0). 2위보다 15.5점 높음.

## 🤖 나랑이: LLM 설명

추천된 사람마다 **나랑이**가 "왜 이 사람인지"를 자연스러운 문장으로 설명해 줍니다. 내 컴퓨터의 **Ollama(gemma3)**를 사용합니다.

- **순위와 점수는 규칙(거르기 + 점수)으로 계산**하고, 나랑이(LLM)는 그 근거를 문장으로 바꾸기만 함
  → LLM은 말을 자연스럽게 만들지만 맞다는 보장은 없어서, 판단은 규칙에 맡기고 설명만 LLM에게 맡김
- LLM에게는 계산된 사실만 줌: 순위, 최종 점수, 나 기준/상대 기준 점수, 겹치는 관심사, 항목별 점수와 근거
- 프롬프트 규칙: 사실에 없는 내용(외모, 직업, 지어낸 경험) 금지, 점수 높은 항목 2~3개를 근거로, 서로 점수 차이가 크면 솔직하게 말하기
- 1위는 자동으로 설명하고, 다른 후보는 "나랑이에게 물어보기" 버튼으로 설명
- Ollama가 꺼져 있거나 다른 사람 컴퓨터에서 열면 **규칙으로 만든 설명**을 대신 보여 줌

### 나랑이 연결 방법 (처음 한 번)
1. Ollama 실행: `ollama run gemma3`
2. 이 사이트 주소를 허용하는 환경 변수 설정: `OLLAMA_ORIGINS` = `https://cjh050728.github.io`
   - Windows: 시작 → "시스템 환경 변수 편집" → 환경 변수 → 새로 만들기
3. 작업 표시줄에서 Ollama를 완전히 종료한 뒤 다시 실행
4. 사이트에서 내 프로필 카드의 "🤖 나랑이" → 연결 확인 (크롬이 로컬 네트워크 접근을 물으면 허용)

## 추천 화면 기능

- **공통점 문장**: "두 분은 러닝, 노래, OTT를 좋아해요 · 둘 다 저녁형이에요"
- **항목별 궁합**: 항목마다 나 입장과 상대 입장 비슷함의 평균을 %로 표시
- **첫 대화 추천**: 겹친 관심사로 질문 2개를 만들어 줌 (AI 없이 정해진 문장 틀 사용)
- **뱃지**: 프로필 정보로 자동 표시 (🌙 밤형 인간, 💬 연락 많이 하는 편, ☕ 카페파 등)
- **좋아요 → 매칭**: 내가 좋아요를 누르고 **상대 기준 점수가 60점 이상**이면 상대도 호감이 있는 것으로 보고 매칭. 가상 프로필은 직접 좋아요를 누를 수 없어서, "서로 점수" 로직의 상대 기준 점수로 대신 판단함
- **연인 / 친구 전환**: 홈 화면에서 바로 바꿀 수 있음
- **채팅**: 매칭된 사람만 채팅할 수 있음. 인사든 뭐든 직접 입력해서 보내고, 추천 질문은 원할 때만 골라서 쓸 수 있음
  - 추천 질문(관심사별 질문, MBTI, 주말 계획, 이상형 등 최대 12개)에는 **질문에 맞는 답**을 함. 상대가 그 취미를 안 하면 "잘 안 해요, 대신 ○○ 좋아해요"처럼 솔직하게 답함
  - 상대가 나한테 질문한 뒤 내가 대답하면, **무엇을 물어봤는지 기억하고 내 대답이 긍정인지 부정인지** 보고 맞게 반응함 (예: "오늘 하루 어땠어요?" → "피곤했어요" → 다정한 사람은 "고생 많았어요, 푹 쉬어요")
  - 가상 프로필은 AI 없이 **프로필 정보로 자동 답장**: 내가 꺼낸 주제가 상대 관심사면 좋아하는 답, 아니면 자기 관심사로 화제를 돌림. 연락 스타일이 "자주"면 답장이 빠르고 이모티콘이 많고, "가끔"이면 느리고 짧게 답함
  - 대화 내용은 이 브라우저에 저장됨

## 회원가입과 저장

- 닉네임 + 비밀번호로 가입하고, 가입하면 바로 프로필 설정 화면으로 이동
- GitHub Pages는 서버가 없어서 계정과 프로필은 **각자 브라우저(localStorage)에만** 저장됨
  - 같은 브라우저에서는 다시 로그인하면 프로필이 남아 있음
  - 가입한 사람끼리는 서로 보이지 않고, 각자 가상 프로필 36명과 매칭됨
  - 비밀번호는 해시로 바꿔 저장하지만 보안 기능은 아니므로 실제 비밀번호를 쓰지 않도록 안내함
- "예시 계정으로 둘러보기"로 가입 없이 바로 결과를 볼 수 있음

## 실제 서비스라면 필요한 것

- 가입한 사람끼리 매칭하려면 프로필을 모아 둘 서버와 데이터베이스
- 진짜 로그인과 본인 인증
- 신고·차단, 프로필 비공개, 탈퇴(데이터 삭제)
- 사진 도용 방지와 개인정보 노출 최소화

## 다른 방법과 비교

| 방법 | 이 프로젝트에서 |
|---|---|
| 규칙 + 가중치 | 사용 (거르기, 배점) |
| 유사도 공식 | 사용 (자카드, 거리) |
| 임베딩 | 사용 안 함: 후보는 잘 추리지만 왜 그 결과인지 정확히 설명하지 못함 |
| LLM 판단 | 사용 안 함: 설명이 자연스러워도 맞다는 보장이 없음 |

과제의 핵심이 "1위의 이유를 말하는 것"이라, 이유를 숫자로 정확히 보여줄 수 있는 규칙 + 유사도 공식만 사용했습니다.

## 실행 방법

`index.html`을 브라우저로 열면 됩니다. GitHub Pages를 켜면 링크로도 열 수 있습니다.
